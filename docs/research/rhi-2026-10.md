## 1. Game discovery, engine, API, bitness

### 1.1 Launchers (`Services/GameDetectionService*.cs`)
Interface `IGameDetectionService`; every `FindXxxGames()` returns `List<DetectedGame>` (`Models/DetectedGame.cs`), failures isolated per store.
- Steam, `GameDetectionService.Steam.cs:FindSteamGames`: registry `HKCU/HKLM SOFTWARE\Valve\Steam` (and WOW6432Node) `SteamPath`; `steamapps\libraryfolders.vdf` parsed by regex `"path"\s+"..."`; each `appmanifest_*.acf` gives `name`, `installdir`; AppID from file name (`ExtractAppIdFromAcfFilename`). Root = `steamapps\common\<installdir>`.
- GOG, `.Platform.cs:FindGogGames`: `HKLM\SOFTWARE\GOG.com\Games\*` values `GAMENAME`, `PATH` (also WOW6432Node).
- Epic, `FindEpicGames`: `%ProgramData%\Epic\EpicGamesLauncher\Data\Manifests\*.item` (JSON, regex extraction of `DisplayName`, `InstallLocation`, `CatalogNamespace`, `AppName`).
- EA App, `FindEaGames`: 5 methods: `%ProgramData%\EA\content\*\__Installer\installerdata.xml` (`gameName`, `defaultInstallPath`), `HKLM\SOFTWARE\Wow6432Node\Origin Games`, `SOFTWARE\EA Games`, default EA folders, EA Desktop JSON config scan.
- Ubisoft, `FindUbisoftGames`: `HKLM\SOFTWARE\(WOW6432Node\)Ubisoft\Launcher\Installs\*\InstallDir` (folder name used as title), plus settings.yml and default folders.
- Battle.net, `FindBattleNetGames`: Uninstall registry entries filtered by Publisher in {Blizzard Entertainment, Activision, Activision Blizzard}, skip launcher; also `Battle.net.config` and default folder.
- Rockstar, `FindRockstarGames`: uninstall registry, `<launcher InstallFolder>\titles.dat` regex `"InstallFolder"`, default `Program Files\Rockstar Games`.
- Xbox/Game Pass, `GameDetectionService.Xbox.cs:FindXboxGames`: WinRT `PackageManager.FindPackagesForUser("")`, store-signed non-framework packages, game = has `MicrosoftGame.config`; fallbacks `.GamingRoot` files, registry, folder scan (`FindXboxGamesFallback`, `ParseGamingRootFile`, `ResolveXboxGameRoot`). Xbox paths (`WindowsApps`) are access-denied so API/engine are inferred (see 1.3).
- **itch.io**: README and docs claim it, but `grep -i itch` over all .cs returns nothing. Only manual add (drag-and-drop exe, `DragDropHandler.Exe.cs`, Add Game button) can cover it. Treat as marketing only.
- Manual add: drag `.exe` onto the window; library persisted in `game_library.json` (`Services/GameLibraryService.cs`), disconnected-drive games stay cached.
- Noise filtering: manifest `blacklist`/`blacklistPrefixes` (non-games such as "Windows", "Wallpaper Engine", DLC entries), `splitGames` (one folder to several cards, e.g. Mass Effect Legendary), `installPathOverrides` (subfolder for mods, `Win64|WinGDK` candidates). User-selectable exe via `launchExeOverrides`.

### 1.2 Engine and engine version (`GameDetectionService.cs`)
`DetectEngineAndPath(rootPath)` (cached per root, `_engineCache`) returns the folder where mods must be placed plus `EngineType` (`Models/EngineType.cs`: Unreal, UnrealLegacy, Unity, REEngine, Unknown plus free-text labels from manifest `engineOverrides`):
1. Unreal: `FindUEBinariesFolder` walks up to depth 5, skips `Engine\` and bonus-content folders (`_skipFolders`), finds `Binaries\{Win64|Win32|WinGDK}` containing an exe; prefers folders with `*Shipping*.exe`. `IsUnrealLegacy` (UE3) = `TAGame` folder, or `Engine\Config\BaseEngine.ini` with Binaries but no `*Shipping*.exe`, or any `*.u`/`*.upk` files. UE3 gets no RenoDX offer.
2. Unity: `UnityPlayer.dll` within depth 2, else `IsUnityGame`: `Mono`, `MonoBleedingEdge`, `il2cpp` folders, `GameAssembly.dll`, or `<x>_Data` subfolder markers (`Resources\unity_builtin_extra`).
3. RE Engine: `re_chunk_000.pak` shallow.
4. Else Unknown; mod folder = shallowest folder with an exe (`FindShallowExeFolder`).
- UE version, `DetectUeVersion(installPath)`: finds `<root>\Engine\Binaries\Win64\CrashReportClient.exe` (or `-Win64-Shipping`), reads `FileVersionInfo` Major 4..6 -> "5.4.3"; fallback `Engine\Build\Build.version` JSON (`MajorVersion/MinorVersion/PatchVersion`); fallback FileVersion of `*-Shipping.exe` or largest exe. Result becomes `EngineHint` ("Unreal Engine 5.x") and drives UE4 vs UE5 decisions. Manifest `engineHintOverrides` overrides it; PCGW engine name is a fallback (`MainViewModel.BuildCards.cs:1335`).

### 1.3 Graphics API (`Services/GraphicsApiDetector.cs`, `ViewModels/MainViewModel.GameMatching.cs:DetectGraphicsApi` / `_DetectAllApisForCard`)
- PE import-table parser (own code, no library): reads 4 KB header, handles PE32 (0x10B) and PE32+ (0x20B), builds RVA to file offset map from sections, walks the import descriptors (20 bytes each) and the delay-load directory (32 bytes each), maps DLL names via `DllMap`: d3d8, d3d9, d3d10/d3d10_1, d3d11, d3d12, vulkan-1, opengl32. `dxgi.dll` alone infers DX12. Delay-load table is scanned only if no explicit DX11+ import was found (UE4 games that delay-load d3d12 would otherwise be promoted wrongly). Priority DX12 > Vulkan > DX11 > DX10 > OpenGL > DX9 > DX8. `DetectAllApis` returns the whole set (dual-API badge "DX11/12 + VLK", `IsDualApi`, `GetMultiLabel`). Cache `%LocalAppData%\RHI\api_cache.json`, key `path|lastWriteTicks`.
- Resolution order in `DetectGraphicsApi`: user per-game override; manifest `graphicsApiOverrides` (comma list, e.g. "DX12, VLK"); WindowsApps path -> infer from engine (UE5 hint -> DX12, UE4 -> DX11, UE3 -> DX9, Unity -> DX11, RE Engine -> DX12); Unity `boot.config` `gfx-device-type` (`DetectUnityFromBootConfig`, default DX11); `D3D12Core.dll` in any subfolder = DX12; PE scan of main exe (`PeHeaderService.FindGameExe` = largest top-level exe); then every non-system DLL in the folder (skips dxgi.dll, system/CRT/middleware list `IsSystemOrRuntimeDll`); then `Bin64, Bin, x64, Win64, Binaries, Binaries\Win64, Binaries\WinGDK` exes. OpenGL-only result on Unity/UE/RE Engine is overridden to DX11 (those engines statically link opengl32). UE5+ never reports DX11 (`IsUe5OrHigher`). PCGamingWiki data upgrades DX11/Unknown -> DX12 or fills Unknown (`BuildCards.cs:~820`).
- PCGW data: `database/pcgw_data.json` (55,566 games: steam_appid, config_path, engine) from RHI repo (`Services/PcgwService.cs`), live fallback `pcgamingwiki.com/api/appid.php?appid=` and `w/api.php?action=opensearch`; parses "Other information - API" (`Models/PcgwApiInfo.cs`: DX9/10/11/12, Vulkan, OpenGL, Metal flags, ConfigPath, ConfigPathXbox, Engine). Generator scripts in `tools/pcgw-fetch/`.
- Community DB idea: `game-db/` (python seed/merge scripts; `game_db.json` with api, bitness, engine, install_subpath, exe_relative, ids). Users export a "Game Report" zip (`GameReportEncoder.cs`) and paste into Discord. Not fetched by the app as far as I read (README says "publish to wherever RHI fetches it": unverified/unfinished).

### 1.4 Bitness
`Services/PeHeaderService.cs:DetectArchitecture` reads `Machine` field at PE header+4 (0x014C = 32-bit, 0x8664 = x64). `ResolveIs32Bit` (`MainViewModel.GameMatching.cs:289`) priority: user override ("32"/"64"), manifest `thirtyTwoBitGames`/`sixtyFourBitGames`, then PE machine of the game exe (cached in `_bitnessCache`). Bitness picks ReShade32/64, `.addon32/.addon64`, DXVK `x32/x64` folder, DisplayCommander/ReLimiter variant, dgVoodoo, Feeder.

### 2.2 Matching a game to a mod (`GameDetectionService.MatchGame`, `NormalizeName`)
- `NormalizeName`: strip TM/R/C, Unicode FormD and drop diacritics, lowercase, remove everything not a-z0-9.
- Order: (0) user/manifest `wikiNameOverrides` (exact then normalised key); (1) exact normalised equality; (2) game name contains mod name (longest wins, "Code Vein GOTY" -> "Code Vein"); (3) mod name starts with game name, rejected when the extra suffix is only roman numerals/digits (sequel guard). Manifest `wikiUnlinks` disconnects a game completely; `wikiNameOverrides` (55) fixes store-title mismatches.
- Fallback when no named mod (`ViewModels/MainViewModel.BuildCards.cs:156`): `engine == Unreal -> genericUnreal`, `Unity -> genericUnity`, UnrealLegacy none. Generic URLs (`Services/WikiService.cs`): `https://github.com/clshortfuse/renodx/releases/download/snapshot/renodx-unrealengine.addon64`, Unity `https://github.com/NotVoosh/renodx-unity/releases/download/snapshot/renodx-unityengine.addon64` and `.addon32` (32-bit chosen via `card.Is32Bit`, `MainViewModel.Install.cs:~808`).
- **UE-Extended decision** (`BuildCards.cs:440-515`): `useUeExt = !noUeExtended && (!hasNamedMod || isNativeHdr || userOptIn) && !hasNamedAddonOnDisk && (addonOnDisk == renodx-ue-extended.addon64 || userOptIn || isNativeHdr || generic UE fallback)`. In plain words: every Unreal game without a named mod defaults to UE-Extended (user can toggle back to plain generic UE: `ToggleUeExtended`, `Install.cs:164`). Manifest lists: `nativeHdrGames` (45, forces UE-Extended even when a named mod exists), `ueExtendedGames`, `noUeExtendedGames` (highest priority block), `ueExtendedCompatibility` (per-game `hdr`/`lut` booleans), `snapshotOverrides` (19 manual URL fixes), `forceExternalOnly` (redirect-only cards to Nexus/Discord).
- UE-Extended download URL: `https://marat569.github.io/renodx/renodx-ue-extended.addon64` (constant `DefaultUeExtendedUrl`, overridable via manifest `componentUrls.ueExtended`; host-specific override table `ModInstallService._addonUrlOverrides`, `Services/ModInstallService.cs:38`).
- Also: DevKit (`renodx-devkit.addon32/64`) and `renodx-dlssfix.addon64` from `clshortfuse/renodx/releases/download/snapshot/` as picker addons (`AddonPackService.cs`).

### 2.3 Install and "auto pulling" of builds
- `ModInstallService.InstallAsync`: downloads to `%LocalAppData%\RenoDXCommander\downloads\` (cache), validates `MZ` PE header (rejects HTML error pages), copies to the addon deploy dir: `GetAddonDeployPath` = `[ADDON] AddonPath` from the game's reshade.ini if set (relative to game dir) else the game dir. Records in a JSON DB (`InstalledModRecord` with `RemoteFileSize`, `FileHash`).
- Update detection `CheckForUpdateAsync` (`ModInstallService.cs:277`): HEAD `Content-Length` compared to the size stored at install time; no Content-Length -> assume no update. For `*.github.io` hosts and any URL containing `/snapshot/` or `/latest/` (`ShouldUseDownloadCheck`) it downloads the file and compares SHA hash with the stored `FileHash` (GitHub Pages lies about length; snapshot builds can change at identical size). That is the whole "auto pull of ShortFuse builds": the rolling `snapshot` release assets are re-fetched and hash-compared; there is no version number.
- "Update All" (`Services/UpdateOrchestrationService.cs`, toolbar button) updates ReShade, RenoDX, ReLimiter, Display Commander, OptiScaler, REFramework, dedups URLs via `ResolveSnapshotUrlPublic`, respects per-game exclusions (`UpdateInclusionHelper.cs`), re-applies per-game `[renodx]` ini overrides after updating. Background check every 4 h.

- Peak brightness: `ApplyPeakNits` writes `ToneMapPeakNits` into `[renodx-preset1..3]` (user-selectable which presets; creates missing sections) from a global setting.

### 3.2 Engine.ini
- Location (`ResolveEngineIniDir`, line 728): manifest/PCGW override (a path containing `\` is used as directory; `|`-separated candidates; env vars expanded); else project name = folder above `Binaries` (`ResolveUeProjectName`, falls back to grandparent if an AppData folder with that name exists). - Keys written when HDR is wanted (`ApplyEngineIniHdrSettings`, line 847; line-based append to preserve duplicate keys; only appends missing keys; then **sets the file read-only** so the engine cannot overwrite):

Per-game custom Engine.ini fragments: manifest `engineIniFiles` (game -> filename) fetched from `https://raw.githubusercontent.com/RankFTW/rhi-repo/main/engine-files/<file>` (cached `%LocalAppData%\RHI\engine-files`), merged with `ApplyEngineIniFromFileAsync` (e.g. Black Myth: Wukong file contains `[SystemSettings] r.HDR.EnableHDROutput=1`); this replaces the standard keys. ## 4. Luma Framework (`Services/LumaService.cs`, `ViewModels/MainViewModel.Install.Luma.cs`)

- Catalog: **scrapes the Luma wiki** `https://github.com/Filoppi/Luma-Framework/wiki` with HtmlAgilityPack.

## 6. ReShade management

- Sources (all staged under `%LocalAppData%\RHI\`):

Download the setup exe, verify `MZ` and size >500 KB, extract `ReShade64.dll`/`ReShade32.dll` from the exe with bundled 7z (`Services/ReShadeUpdateService.cs`). Staged `reshade\`.
  - Non-addon ("No Addons"): same page, regex `ReShade_Setup_([\d.]+)\.exe` without `_Addon` (`Services/NormalReShadeUpdateService.cs`) -> `reshade-normal\`.
  - Nightly: `https://nightly.link/crosire/reshade/workflows/build/main/ReShade%20(64-bit).zip` and `(32-bit)`, update detected by remote zip size (`Services/ReShadeNightlyService.cs`) -> `reshade-nightly\`.

- Channels per game (`AuxInstallService.cs:129`: `Stable`, `Nightly`, `Custom`, or a version string = Legacy; plus "No Addons" = `TypeReShadeNormal`; "Global" inherits Settings default). Legacy/Custom are excluded from update checks (`CheckReShadeUpdateLocal` compares installed file size with the staged DLL, so "update available" = size differs).
- DLL naming (`MainViewModel.Install.Luma.cs:19 ResolveAutoReShadeFilename`): DX11/DX12 -> `dxgi.dll` (default); else DX9 -> `d3d9.dll`; DX8 -> `d3d8.dll`; OpenGL-only -> `opengl32.dll`. XNA/GAC games (Terraria) via `AuxInstallService.GacSymlink.cs` (`gacSymlinkGames`).
- Install flow `AuxInstallService.Install.cs:InstallReShadeAsync`: remove old file if name changed, `BackupForeignDll`, copy staged DLL, `MergeRsIni`, sync shaders (`ShaderPackService.SyncGameFolder`), save record in `aux_installed.json`.
- Vulkan (`Services/VulkanLayerService.cs`): needs admin. Copies staged `ReShade64.dll` to `C:\ProgramData\ReShade\`, writes `ReShade64.json` (bundled file `ReShade64.json`: `layer.name=VK_LAYER_reshade`, `type=GLOBAL`, `library_path=.\ReShade64.dll`, `api_version=1.3.268`, `implementation_version=1`, `disable_environment {DISABLE_VK_LAYER_reshade_1=1}`, device extension `VK_EXT_tooling_info`), registers it as a DWORD value 0 named by the manifest path under **`HKLM\SOFTWARE\Khronos\Vulkan\ImplicitLayers`**. Installed = registry value + manifest file + DLL all present. Per game: `reshade.ini` from `ReShade.Vulkan.ini` (adds `PreprocessorDefinitions=RESHADE_DEPTH_LINEARIZATION_FAR_PLANE=1000.0,RESHADE_DEPTH_INPUT_IS_UPSIDE_DOWN=0,RESHADE_DEPTH_INPUT_IS_REVERSED=1,RESHADE_DEPTH_INPUT_IS_LOGARITHMIC=0` and no `[OVERLAY]`) plus `RDXC_VULKAN_FOOTPRINT`.
